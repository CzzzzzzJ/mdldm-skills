# Content Script Local Draft

为麦当 mdldm 已经完成或正在形成的中文自媒体内容，生成可继续编辑、录制或直接发布的本地 Markdown 内容。

默认服务麦当 mdldm 的内容工作流。用户用中文时，保持中文输出；保留“兄弟们、不端着、玩点实际的”这类自然口语，但不要把全部平台文案写成同一个版本。

## 模式路由

- 用户要观点型正文、个人提升内容、原始口播整理或非教程型商单脚本：完整读取 [`references/mdldm-viewpoint-writing.md`](references/mdldm-viewpoint-writing.md)，再写作。
- 用户要完整发布素材包、封面标题或多平台文案：使用本文件后续流程；只有原稿本身是观点型内容时，才同时读取观点写作参考。
- 用户只要大纲或首批草稿：按当前阶段交付，不擅自扩成完整发布包。

## 核心原则

### 1. 封面负责点击，不负责总结

封面不是课程目录，也不是内容摘要。

封面唯一的任务是让目标用户在一秒内知道：

1. 这件事和我有什么关系；
2. 我点开能学到什么或得到什么；
3. 它是否可能带来一个我在意的结果。

视频里的方法、步骤、阶段、公式、模块和知识点，默认放进正文，不堆在封面。

### 2. 先写用户收益，再写创作者动作

优先使用：

```text
用户怎么得到某个结果？
用户会避免什么损失？
用户会学会什么具体能力？
```

谨慎使用：

```text
我做了……
我研究了……
我把一年经验整理成了……
```

除非“创作者亲自完成了一个反常识结果”本身就是最强证据，否则标题应从用户视角出发。

### 3. 一张封面只有一个承诺

默认只保留：

```text
一个主标题
+ 可选的一个短角标
```

主标题讲用户结果。

角标只能补充一个额外点击理由，例如：

- 免费开源；
- 实测；
- 完整教程；
- 附模板；
- Skill 已挂载。

不要同时出现主标题、副标题、五个功能、七个步骤、三个案例和下一期预告。

### 4. 强结果必须有内容证据

点击驱动不等于夸大承诺。

标题里的结果必须能被原稿、演示或真实案例支撑。

涉及赚钱、收入、涨粉、就业、健康等强结果时：

- 可以表达“机会、可能、路线、第一步、验证方法”；
- 不写“保证赚钱、必涨粉、一定成功、轻松月入”；
- 最好把承诺落到可验证的中间结果，例如“第一笔真实收费”“第一款产品”“第一个可用方案”。

### 5. 发布素材必须是完整包

用户说“发布素材”时，默认交付完整本地 Markdown，不只给几个标题。

完整包通常包含：

1. 内容定位与统一传播角度；
2. 主推封面、备选标题和封面画面方案；
3. 封面生成 Prompt，但不默认实际生成图片；
4. B 站标题、简介、章节、标签、置顶评论；
5. 小红书独立文案；
6. 抖音 / 视频号文案；
7. 动态、公众号或社群文案；
8. 可复用金句；
9. 发布 Checklist。

如果同目录已有成熟发布素材，优先沿用其栏目结构；点击逻辑仍以本 Skill 为准。

## 触发边界

使用本 Skill：

- 根据用户的原始口播或观点生成本地正文草稿；
- 生成或重写观点型商单脚本、脚本大纲；
- 补一篇视频、课程、文章或产品的发布素材；
- 重写封面标题和平台标题；
- 从已录制口播生成多平台文案；
- 小红书需要与其他平台单独设计；
- 内容同时发布一个开源项目、模板、插件或 Skill；
- 用户要求把最终成品写入本地 Markdown。

不要使用本 Skill：

- 用户只想讨论抽象营销理论；
- 用户要直接操作平台发布，但没有要求准备文案；
- 任务是纯网页设计、图片生成或视频剪辑；
- 用户只要求一句简单改写，且不需要发布包。

## 输入读取顺序

1. 完整读取用户指定或在对话中提供的原稿、口播、脚本；当前用户原话优先于旧模板；
2. 读取同目录 2—3 份已经完成的发布素材；
3. 查找与本期产品、Skill、课程或项目直接相关的本地说明；
4. 提取用户在当前对话中的明确修正；
5. 以最新用户修正覆盖旧模板和旧习惯。

如果用户的原始口播尚未落库，而任务要求建立项目目录或持续迭代，优先把原始口播单独保存为只读源材料；正文、大纲和发布素材另存版本，不覆盖源材料。

如果用户已经提供本地材料或粘贴了完整内容，不要为了“补资料”反复搜索外网。

## 标准流程

### Step 1：先还原内容事实

提取：

- 这期真正讲了什么；
- 用户最终能学会什么；
- 有哪些真实案例、演示或结果；
- 有什么免费资源、开源项目、Skill、模板或后续产品；
- 哪些说法有证据，哪些只能表达为可能性。

不要先套发布模板。

### Step 2：确定唯一目标用户

用一句话回答：

```text
这期最想吸引哪一种人？
```

目标用户应来自真实场景，例如：

- 已经发内容但不知道卖什么的博主；
- 想用 AI 提高工作效率的职场人；
- 不会设计但需要做海报的运营；
- 能做小工具但不会把项目上线的新手。

不要使用“所有人”“对 AI 感兴趣的人”这种无效受众。

### Step 3：完成点击承诺三问

在写封面前必须回答：

1. 用户点开能学到什么？
2. 看完后最可能发生什么具体变化？
3. 哪个结果最能驱动这类用户点击？

把三个答案压缩成一句口语标题。

优先级：

```text
具体结果 > 用户痛点 > 反常识判断 > 工具或功能名称
```

### Step 4：生成封面标题

默认生成：

- 1 个主推标题；
- 2—3 个真正不同的备选标题；
- 1 个短角标；
- 1 套画面构成；
- 1 段可直接使用的封面 Prompt。

主标题检查：

- 手机缩略图中能否一眼读完；
- 是否使用普通人会说的话；
- 是否明确写出结果或强问题；
- 是否从用户视角出发；
- 删除一个词后是否更有力；
- 是否与视频真实内容一致。

推荐长度不是死规则，但通常控制在两行、约 8—14 个汉字。

### Step 5：设计封面画面

默认使用以下点击结构：

```text
一个大结果标题
+ 一个清晰主体或真人情绪
+ 一个真实证据画面
```

真实证据可以是：

- 产品效果；
- 前后对比；
- 真实界面；
- Skill 输出；
- 成片、网站、数据或案例截图。

画面规则：

- 标题通常占 50%—65% 的视觉权重；
- 证据画面用来增加可信度，不承担讲完整方法；
- 真人存在时，人物要足够大，动作或视线服务标题；
- 不默认做多卡片拼贴、假仪表盘、抽象科技背景；
- 不用“高级感”牺牲一眼看懂；
- 不用金币雨、钞票飞舞等廉价赚钱视觉。

### Step 6：做一次反目录检查

如果封面出现以下任意两项，默认需要继续删：

- 多个步骤；
- 多个阶段；
- 多个功能；
- 多个案例；
- 完整公式；
- 下一期预告；
- 两个以上角标；
- 需要停下来阅读的小字。

把删掉的信息放进简介、配图、时间轴或置顶评论。

### Step 7：分别写平台文案

#### B 站

- 标题可以比封面更完整；
- 结构通常是“用户结果 + 具体内容或免费资产”；
- 简介讲清能学到什么、视频覆盖什么、资源怎么使用；
- 有成片时按真实成片补时间轴，不编造时间；
- 置顶评论承接安装方式、资料、模板或下一步。

#### 抖音 / 视频号

- 前三秒文字只保留一个强事实、强问题或强结果；
- 正文短于 B 站，优先让人看懂“为什么值得看”；
- 不重复讲完整课程目录。

#### 公众号 / 动态 / 社群

- 更像本人自然预告或复盘；
- 保留事实、口语关系和适量背景；
- 不写成统一广告口径。

### Step 8：小红书必须单独设计

小红书正文不能直接复制 B 站简介。

小红书版本至少要做到：

1. 标题独立、短、结果清楚；
2. 笔记本身有完整的可带走价值；
3. 使用短段落和具体场景；
4. CTA 与当前发布载体一致；
5. 给出可直接复制的首次使用模板或行动步骤。

如果同步上架或挂载 Skill：

- 主 CTA 是点击笔记内挂载的 Skill；
- 不在正文同时堆 GitHub、skills.sh、知识站和多个外链；
- 单独提供 Skill 名称、短描述、功能说明、适合谁、不适合谁、权限和边界；
- 置顶评论放首次输入模板；
- 发布前检查 Skill 组件是否真实可见、可用；
- 明确区分“提供路线建议”和“保证结果”；
- Skill 本身要独立有用，不能只是广告入口。

如果 Skill 尚未完成挂载，不要在正式文案中写“已经挂载”。

### Step 9：A/B 测试只改一个变量

需要备选封面时，先决定测试什么：

- 受众宽窄；
- 结果强弱；
- 问句或陈述句；
- 工具名是否出现。

同一轮不要同时改标题、人物、背景、证据截图和颜色，否则无法判断为什么点击率变化。

### Step 10：写入本地文件

- 优先更新或创建与原稿相邻的 `*-发布素材.md`；
- 不只在聊天里给方案；
- 保留用户原稿，不覆盖源内容；
- 用户要求重做时，可以更新上一版发布素材；
- 最终告诉用户准确文件路径和本次最重要的传播角度。

## 通用示例

### 示例 1：知识变现

不推荐：

```text
别急着录课
博主知识变现先走这 7 步
```

问题：在劝用户，像课程目录，没有直接表达用户想得到的结果。

推荐：

```text
怎么靠知识
赚到第一笔钱？
```

角标：

```text
免费开源 Skill
```

### 示例 2：AI 工具

不推荐：

```text
某某工具全功能深度测评
```

推荐逻辑：

```text
它能替用户完成什么具体任务？
这个结果发生后，用户省了什么或得到了什么？
```

工具名可以放进平台标题，封面优先写结果。

### 示例 3：教程内容

不推荐：

```text
安装、配置、工作流、案例完整教程
```

推荐逻辑：

```text
看完能做出什么？
这个结果对哪一种人最有吸引力？
```

步骤和功能放进简介或时间轴。

## 常见错误与修正

### 错误：标题正确但没有点击欲望

原因：它准确总结了视频，却没有写出用户收益。

修正：从“这期讲什么”改成“用户看完会得到什么”。

### 错误：标题围绕创作者自己

原因：使用“我做了、我研究了、我整理了”，用户需要二次翻译。

修正：删掉“我”，直接写用户结果；创作者经历放进简介作为可信证据。

### 错误：封面信息太多

原因：把完整性误当成点击力。

修正：保留一个承诺和一个角标，其余全部下沉。

### 错误：为了赚钱角度写成收入承诺

原因：把“存在变现机会”夸大成“看完一定赚钱”。

修正：承诺方法、路线、第一款产品或验证动作，不承诺最终收入。

### 错误：所有平台复制同一段文案

原因：只完成了内容摘要，没有完成平台适配。

修正：B 站完整解释，小红书独立交付，抖音/视频号压缩钩子，社群保留关系感。

## 最终验证清单

### 内容

- [ ] 已读取原稿和同目录成熟案例；
- [ ] 已确定唯一核心受众；
- [ ] 已提取真实结果和证据；
- [ ] 没有编造案例、数据或功能。

### 封面

- [ ] 一秒能看懂谁该点、点开能得到什么；
- [ ] 只有一个主标题；
- [ ] 最多一个辅助角标；
- [ ] 标题从用户收益出发；
- [ ] 没有课程目录式信息堆叠；
- [ ] 强结果有内容证据；
- [ ] 缩略图状态仍然可读。

### 平台

- [ ] B 站素材完整；
- [ ] 小红书不是 B 站简介的复制版；
- [ ] Skill 上架或挂载时包含独立使用引导；
- [ ] 没有同时塞入多个冲突 CTA；
- [ ] 没有保证赚钱、保证涨粉等红线表达；
- [ ] 已包含置顶评论、动态或社群文案；
- [ ] 已包含发布 Checklist。

### 交付

- [ ] 已写入正确的本地 Markdown；
- [ ] 原稿没有被覆盖；
- [ ] 文件名、产品名、Skill 名保持一致；
- [ ] 没有占位符、重复标题或旧版本口径；
- [ ] 已向用户说明主推封面和文件路径。
